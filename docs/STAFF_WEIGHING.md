# Development staff weighing

This is a test workflow using simulated scale readings. Staff login, role checks and trip assignments are stored in PostgreSQL. The simulator is enabled only when DALUMAGA_STAFF_SIMULATOR=true and NODE_ENV is not production. The API must bind to 127.0.0.1 when the simulator is enabled.

The local API environment is in apps/api/.env. For the current Supabase development project it contains a path to the downloaded CA certificate. Node loads that certificate when the API process starts. Keep the certificate available at the configured path.

The sample accounts were generated by the seed script. On the development computer, open apps/api/.staff-demo-credentials.json to find the weigher, receiver and dispatcher usernames and passwords. This file is ignored by Git and should remain private. The data in it is for testing, not real employees.

Run from the project root:

```powershell
corepack.cmd pnpm db:status
corepack.cmd pnpm dev
```

Open http://localhost:5174 to sign in as dispatcher. Use an Android emulator with Expo SDK 54 to sign in as weigher or receiver. The sample crate named C044 is available for another walkthrough.

1. Sign in as the weigher with connectivity, then disconnect the emulator.
2. Select the available crate, read the simulated scale and save. The phone shows a pending reading.
3. On a second signed-in session, receive the same crate as the receiver and sync it.
4. Reconnect the first emulator and sync. The dispatcher can refresh the office screen to see the difference.

Sessions last 12 hours. A user signs in online and may then capture offline. If the app process closes, the queued events remain on the device, but the user must reconnect and sign in again to load their assignment and sync them. Sign-out while offline clears the local session but cannot revoke the server session until it expires.

For real factory use, add secure device enrollment, protected offline access and retention, audited account provisioning and recovery, HTTPS for deployed clients, operational monitoring, independently verified hardware, and a security review. Do not use the simulated flow for employee or factory data.
